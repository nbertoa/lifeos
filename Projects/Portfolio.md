# Project Portfolio

> **Role:** Canonical portfolio-level view of current projects. Execution details remain in each project's own source of truth.

## Purpose

This document answers four questions quickly:

1. What is intentionally in focus now?
2. What remains active without competing for primary attention?
3. What is being maintained or deliberately put on hold?
4. What project-level decision or milestone should happen next?

Priority is relative and temporary. It exists to resolve competition for attention; it is not a statement of a project's intrinsic value.

## Entry Format

Use this compact structure for each project:

### Project name

- **Priority:** High / Medium / Low, or explicitly unresolved.
- **Outcome:** One sentence describing the durable result.
- **Next milestone or decision:** One meaningful checkpoint.
- **Source of truth:** Repository, document, site, or other execution system.
- **Review trigger:** Event that should cause the portfolio entry to be reconsidered.

## Review Discipline

Review this file when a project is started, completed, intentionally paused, or materially redirected. Avoid calendar-driven bureaucracy unless the portfolio becomes stale in practice.

Do not add individual tasks. If the next item can be completed as a routine action without changing project direction, it belongs in the execution system rather than here.
